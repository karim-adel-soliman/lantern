# Contributing

## Branch naming
Use descriptive branch names such as:
- feature/list-sort
- fix/empty-list
- docs/contributing

## Commit messages
Use Conventional Commits: type(scope): description.

Examples:
- feat(list): add title sorting
- fix(list): handle empty tasks
- docs(contributing): explain contribution rules

Keep commits focused and explain why the change is needed.

## Pull requests and reviews
- Create a branch for each change.
- Open a pull request with a clear description and a linked issue.
- Use Closes #<issue-number> when the pull request resolves an issue.
- Request a review from the other team member.
- Address review feedback and resolve conversations.
- Obtain at least one approval before merging into main.

## Shared history
Do not force-push or rewrite commits that have already been pushed.
Keep generated files and secrets out of Git.
